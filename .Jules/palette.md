## 2024-08-09 - High-Asset Sequence Loading & Accessibility Safeguards
**Learning:** Canvas-based interactive image sequences (e.g., scroll animations with hundreds of frames) present a major UX "dead zone" where users face a static or blank screen while assets preload. To address this without introducing assistive technology noise, implementing a minimalist, CSS-transition-synchronized loader with static/inert `noscript` fallbacks is essential. Furthermore, heavy asset preloading via asynchronous image instantiations must attach load, error, and abort listeners *prior* to setting the `src` attribute to prevent race conditions (especially on cached/instant loads) and avoid indefinite loading freezes.
**Action:** Always wrap heavy assets in a preloading loop that updates a progress-focused ARIA element (`role="progressbar"`), handle fallback error/abort pathways by resolving standard progress states, and clean up the loader completely using `element.remove()` rather than hiding via CSS to keep the DOM clean.
